# 渲染一致性检查（训练样本 vs 原始链路新渲染）

日期：2026-11-26
方法：各元素取训练集前 25 张图与原始链路新渲染图，统一缩到 128×128，比较平均亮度、亮度标准差、平均饱和度（0–1 区间）。

| 元素 | 训练 亮度/对比/饱和 | 新渲染 亮度/对比/饱和 | 判断 |
|---|---|---|---|
| snow_swe | 0.887 / 0.136 / 0.099 | 0.766 / 0.230 / 0.183 | 双峰分布，差异来自有雪窗占比（见下） |
| hurricane_rain | 0.932 / 0.113 / 0.093 | 0.945 / 0.118 / 0.042 | 接近 |
| bloom_chla | 0.745 / 0.261 / 0.162 | 0.779 / 0.210 / 0.170 | 接近 |
| haze | 0.903 / 0.159 / 0.140 | 0.904 / 0.162 / 0.131 | 一致 |
| volcano_so2 | 0.788 / 0.322 / 0.131 | 0.710 / 0.353 / 0.178 | 略偏暗 |

## 边界假设检验

把物理值距最近阈值小于 10%、20%、30% 的窗分别剔除，重算一致率（脚本 `scripts/raw_rescore_boundary.py`，结果 `边界窗重算.json`）：

| 边界余量 | 通过 | 未通过 | 证据不足 |
|---|--:|--:|--:|
| 10% | 9 | 11 | 4 |
| 20% | 9 | 9 | 6 |
| 30% | 9 | 8 | 7 |

**通过数三档都是 9，没有增加。** 边界假设被证伪。

## 结论

1. 渲染不是原因：5 个元素分布一致。snow_swe 逐个图看是双峰——有雪窗约 0.70/0.30、无雪窗约 0.95/0.10，训练与新图的单图统计都落在同一双峰上，聚合均值差异只是抽样里“有雪窗”的比例不同，不是渲染 bug。
2. 等级偏差是真实存在的：模型在明显偏向某一侧的样本上仍会给错等级，不能归咎于取样边界。
3. 方向一致：检出基本正确，严重等级容易被判低一档；coral_dhw、wildfire_smoke 有反向偏高。
4. 与第 5 章“sev 弱于 det”同源——等级判别是当前模型薄弱环节。

## 建议

- 训练/微调时对等级边界样本加权重，或把等级判别拆成独立的回归/序数任务。
- snow_swe 无需复查渲染；后续抽样时固定“有雪/无雪”配额即可。
