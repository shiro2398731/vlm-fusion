# 前端说明

仓库提供**两套官方前端**，都连同一个后端服务：

| 前端 | 文件 | 启动 | 适合 |
|---|---|---|---|
| **HTML（主）** | `web/index.html` | 随服务自动托管：`python -m uvicorn scripts.serve:app --port 8078` → http://127.0.0.1:8078 | 正式演示：分栏、样例缩略图、能力卡、汇总研判 |
| **Gradio** | `web/gradio_app.py` | 先启动上面的服务，再 `python web/gradio_app.py --port 7860` → http://127.0.0.1:7860 | 与 HTML 同一后端、结果一致；只依赖 HTTP 接口，不重复占显存 |

两套前端**共用同一个后端**：Gradio 版不自己加载模型，所有判定都走主服务的 `/api/predict`、`/api/report_aggregate`，因此结果一致。

> `src/webui/app_v2.py`、`src/app_demo.py` 是早期独立 Gradio 版本（自己加载模型），保留作参考，未随本次发布验证，不作为演示入口。

## 1. 主界面（HTML）

打开 http://127.0.0.1:8078 后：

- **顶部状态条**：模型是否已暖机、上次端到端自测（38/38）、当前元素
- **采集方式分栏**：光学 / 热红外 / 被动微波 / 雷达降水 / 测高 / 重力 / SAR / 大气 / 散射计 / 空间天气
- **元素卡片**：中文名、源代号、能力摘要、样例缩略图（优先训练集之外的日期，标「未见日期」）
- **推理**：点缩略图直接跑；也可上传自己的渲染图（文件名含词根会自动推荐元素，如 `*_ndwi` → 洪水）
- **结果区**：结构化 JSON + 中文研判
- **汇总研判**：跑过 2 个以上元素后，点按钮让大模型给综合风险与处置建议
- **大模型配置**：Key/模型（Key 只显示掩码，存本地 `config/llm.json`）
- **工程清单**、**搜索框**
- **快捷键**：`1`–`9` 切分栏、`S` 跑当前样例、`A` 汇总研判（输入框内不触发）

## 2. Gradio 界面

```powershell
# 终端 1：主服务（必须）
.\venv\Scripts\python -m uvicorn scripts.serve:app --host 127.0.0.1 --port 8078

# 终端 2：Gradio
.\venv\Scripts\pip install "gradio>=4.40"
.\venv\Scripts\python web\gradio_app.py --port 7860 --api http://127.0.0.1:8078
```

界面内容：

- 顶部状态（服务地址、是否暖机、端到端结果）
- 采集方式 → 元素 → 样例 三级下拉（样例标注「未见日期」）
- 也可以直接上传渲染图
- 「识别」→ 结构化 JSON + 中文研判
- 「汇总研判」→ 把已识别的多个元素交给大模型综合
- 「清空」→ 重置累计结果

## 3. 大模型（已接通）

两套前端都能直接给出中文评估：

- 页面「大模型接口配置」面板填 Base URL / 模型 / API Key（Key 只显示掩码，存本地）
- 推理结果区有后端选择：`template`（模板生成，无需 key）/ `llm`（大模型生成）
- 大模型不可用时自动降级为模板，并在结果里标 `backend: template(fallback: ...)`
- 实测（2026-11-25）：`report_backend=llm` → `backend: openai:deepseek-flash`，返回摘要、风险、建议

## 4. 两套前端共用的后端接口

| 动作 | 接口 |
|---|---|
| 元素与样例 | `GET /api/catalog` |
| 推理（上传/样例） | `POST /api/predict`（multipart：`element` + `file`） |
| 文件名推荐元素 | `GET /api/route?name=...` |
| 大模型配置 | `GET/POST /api/llm`、`POST /api/llm/test` |
| 状态条 | `GET /api/status` |
| 工程清单 | `GET /api/artifacts` |
| 多元素汇总 | `POST /api/report_aggregate` |
| 样例图片 | 静态 `/images` → `datasets/` |

同源访问，无需跨域配置。

## 5. 文件结构

```text
web/
├─ index.html     主界面：单文件（<style> 样式 / <body> 布局 / <script> 逻辑），无构建
└─ gradio_app.py  Gradio 界面：调 HTTP 接口，约 200 行
```

`web/index.html` 里的 JS 按功能分：`loadCatalog()` 拉元素 → `render()` 渲染卡片 → `runSample()/upload()` 推理 → `aggregate()` 汇总 → `loadStatus()/loadArtifacts()/loadLLM()`。

## 6. 常见定制

| 想改什么 | 改哪里 |
|---|---|
| 标题 / 主题色 | `web/index.html` 的 `<title>` 与 `:root` 变量 |
| 分栏顺序、分组名 | `element_groups()`（`scripts/serve.py`） |
| Gradio 端口/接的后端 | `--port`、`--api`（或环境变量 `VLM_API`） |
| 局域网访问 | `--host 0.0.0.0`；界面没有鉴权，只建议内网演示 |

## 7. 样例来源

页面缩略图都是**渲染后的指数图**（物理量 → 固定色标），来自公开卫星产品，不是网络图片。标「未见日期」的来自按日期留出的验证集，训练时没见过这些日期。

## 8. 限制

- 两套界面都没有登录/鉴权，不要直接暴露公网
- 必须通过服务打开（`file://` 双击无效）
- 样例图优先读本地 `datasets/`；本地没有时自动回退到仓库 `demo_samples/`（114 张，按源/元素分目录）
- Gradio 版需要先有主服务；主服务未启动时界面会提示“服务不可用”
